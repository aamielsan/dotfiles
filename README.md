# dotfiles

My macOS setup as a single [mise](https://mise.jdx.dev) config. This repo **is**
`~/.config/mise`: `mise bootstrap` reads it and installs tools and apps, links
dotfiles, clones my Neovim config and applies macOS settings. No Homebrew, no
install scripts.

## New machine

1. Install the Xcode Command Line Tools (git, C compiler):
   ```sh
   xcode-select --install
   ```
2. Install mise:
   ```sh
   curl https://mise.run | sh
   ```
3. Clone this repo into `~/.config/mise` and apply it. On a work laptop add
   `-E work` (see [Modules](#modules)):
   ```sh
   ~/.local/bin/mise -E work bootstrap --adopt aamielsan/dotfiles
   ```
   It asks for your password once (app installs need sudo). If it stops because
   a dotfile already exists as a real file, move that file away and run it again.
4. Remember the module choice for this machine, so plain `mise bootstrap` works:
   ```sh
   echo 'env = ["work"]' > ~/.config/mise/miserc.local.toml
   ```
5. Open Ghostty, log out and back in (trackpad settings), then do the
   [manual steps](#manual-steps).

## Day to day

| I want to… | Do this |
|---|---|
| Re-apply everything after editing | `mise bootstrap` (`--dry-run` first to preview) |
| See what differs from the config | `mise bootstrap status` |
| Add a CLI tool | `mise use -g <tool>` (writes to `config.toml`), commit |
| Update tools | `mise upgrade`, then `mise bootstrap` (repoints the Docker buildx and compose plugins), commit `mise.lock` / `mise.work.lock` |
| Add a dotfile | put it in `home/`, add a line under `[dotfiles]`, `mise dotfiles apply` (links dotfiles only) |
| Add a GUI app | add `"brew-cask:<name>" = {}` under `[bootstrap.packages]` ([find names](https://formulae.brew.sh/cask/)) |
| Edit a dotfile | edit it in place (`~/.zshrc` etc. are symlinks into `home/`) |

GUI apps update themselves; mise only installs them.

## Layout

| Path | What |
|---|---|
| `config.toml` | Shared setup for every machine: tools, apps, dotfiles, macOS settings |
| `config.work.toml` | The `work` module: DNB-only tools, aliases, git identity, SSH host, fork sync |
| `home/` | Dotfile sources, mirroring `$HOME` |
| `mise.lock`, `mise.work.lock`, `locks/` | Exact tool versions and checksums. Generated by mise; commit them |
| `miserc.local.toml` | Per-machine module choice. Not committed |

## Modules

A module is a `config.<name>.toml` file that only applies on machines that
choose it. Currently there's one, `work`. A machine picks modules in
`~/.config/mise/miserc.local.toml`:

```toml
env = ["work"]
```

To add one (e.g. `personal`), create `config.personal.toml` and list it there.
To remove a module from a machine: drop it from `env`, then
`mise bootstrap unapply <name>`.

Things that only some machines have hook in through files that may or may not
exist: `.zshrc` sources `~/.aliases.work` if present, `.gitconfig` includes
`~/.gitconfig.work` for repos under `~/workspace/dnb/`, and `~/.ssh/config`
includes everything in `~/.ssh/config.d/`.

## What's set up where

- **Shell:** zsh with [Zim](https://zimfw.sh) (modules in `home/.zimrc`, it
  installs itself on first start). `.zprofile` sets environment and PATH,
  `.zshrc` does interactive setup. Vi keys: Esc for normal mode, `k`/`j` search
  history. fzf (Ctrl-R, Ctrl-T) and zoxide (`z <dir>` jumps to any folder
  you've visited). Git aliases come from Zim's git module with a lowercase
  prefix (`gf` fetch, `gr` rebase, `gb` branch, …); `gh` stays the GitHub CLI.
- **Terminal:** Ghostty opens straight into the tmux session `main`. tmux
  prefix is `C-a`: `\` and `-` split, `hjkl` move, `v` opens the pane's
  scrollback in Neovim; `y` in copy mode copies to the system clipboard. The
  status bar sits at the top and highlights the current window; the session
  name flips colour while the prefix is held.
- **Keyboard:** Caps Lock is Ctrl when held and Esc when tapped
  (Karabiner-Elements; the rule is in `home/.config/karabiner/`). Vim keys
  everywhere: zsh, tmux copy mode, Neovim, and IntelliJ through IdeaVim, whose
  `home/.ideavimrc` mirrors the Neovim keymaps.
- **Workspace:** repos go in `~/workspace/personal/` (every machine) or
  `~/workspace/dnb/` (work; uses the work git identity), one folder per repo.
  To work on several branches of one repo at once, `wma <branch>` makes a git
  worktree in `<repo>__worktrees/` and opens a tmux window in it ([workmux](https://github.com/raine/workmux)).
  `wml` lists them, `wmx <branch>` removes one (worktree, window and branch).
  Closing the window keeps the worktree; `wmo <branch>` reopens it. `z` looks
  in the current repo or worktree first.
  At work, a LaunchAgent keeps my server-side fork's `master` equal to
  upstream's (`gh repo sync`, at login and hourly, fast-forward only).
- **Git:** `home/.gitconfig`, global ignore in `home/.config/git/ignore`.
- **Neovim:** config lives in its own repo,
  [aamielsan/nvim](https://github.com/aamielsan/nvim), cloned to
  `~/.config/nvim`. mise provides Neovim and the runtimes; Mason (inside
  Neovim) installs language servers and formatters.
- **Kotlin in Neovim:** the language server comes from mise for now, because
  Mason's package can't download it
  ([mason-registry#17323](https://github.com/mason-org/mason-registry/pull/17323)).
  Open Neovim inside the Gradle project you work on; the first open imports it
  (under a minute), later opens take seconds. `:lsp restart` re-imports. It
  doesn't follow Gradle `includeBuild` yet
  ([kotlin-lsp#109](https://github.com/Kotlin/kotlin-lsp/issues/109)), so use
  IntelliJ for code in included builds such as `common-kotlin`.
- **Claude Code:** installed by mise (raicode can only install it with
  Homebrew). At work, launch it through `raicode`.
- **Containers:** `colima start` before using Docker (it isn't started
  automatically). For amd64-only images, `colima start --vz-rosetta`.
  `docker buildx` and `docker compose` work as plugins (linked by the bootstrap
  hook).
- **Whiteboard:** tldraw offline. Its Develop → Install Agent Skills lets
  Claude Code draw on the canvases you have open.

## Files other tools write

These live outside the repo on purpose. Each tool creates and owns its own:

| Path | Written by |
|---|---|
| `~/.zshenv`, `~/.raicode/` | `raicode manage fix-certs` (Zscaler certificate, work laptop only) |
| `~/.colima/` | Colima: the VM and its settings |
| `~/.docker/config.json` | Docker: registry credentials |
| `~/.zim/` | Zim: modules, downloaded on first shell start |
| `~/.local/share/nvim/` | Neovim: plugins, Mason servers, treesitter parsers |
| `~/.cache/nvim/kotlin-lsp/` | Kotlin LSP: an index of about 2 GB per Gradle build opened (each folder with a `settings.gradle.kts`), plus a copy when two Neovims open the same one; safe to delete |
| `~/.local/share/mise/`, `~/.local/state/mise/` | mise: installed tools and bootstrap state |
| `~/.config/karabiner/karabiner.json` | Karabiner: which rules are enabled |
| `~/Library/Application Support/JetBrains/` | IntelliJ: settings, plugins (IdeaVim), memory |
| `~/Library/Application Support/tldraw/` | tldraw offline: app data, and `server.json` with the local agent API's port and token |
| `~/skills/tldraw-offline/`, `~/.claude/skills/tldraw-offline/`, `~/.claude/agents/tldraw-offline.md`, the `SubagentStart` hook in `~/.claude/settings.json` | tldraw offline's Develop → Install Agent Skills (remove with Develop → Uninstall Agent Skills) |

Two catches:

- Colima writes an `Include` into `~/.ssh/config`, which is a file in this
  repo. Start it the first time with `colima start --ssh-config=false`; it
  remembers the setting.
- `fix-certs` only edits `~/.zshenv` on its first run. If that line goes
  missing, move `~/.raicode/env.sh` away and run `fix-certs` again.

## Manual steps

- Caps Lock (hold for Ctrl, tap for Esc): open Karabiner-Elements, then in
  System Settings turn on its driver (General → Login Items & Extensions →
  Driver Extensions) and allow Karabiner-Core-Service under Privacy & Security →
  Input Monitoring. Until the driver is on, Caps Lock stays Caps Lock. Then in
  Karabiner: Complex Modifications → Add predefined rule → enable "Change
  caps_lock to control if pressed with other keys, to escape if pressed alone".
- SSH keys: put `github-personal` (and `github-dnb` and `gitlab-dnb` at work) in
  `~/.ssh/` and add each `.pub` to its account. Check with `ssh -T git@github.com` and
  `ssh -T dnb@dnb.ghe.com` (the DNB host's SSH user is `dnb`, not `git`).
- IntelliJ: turn on Settings → Backup and Sync with your JetBrains account; it
  restores settings and plugins (IdeaVim) on a new machine. Point the project
  SDK at `~/.local/share/mise/installs/java/corretto-25`.
- Work laptop: run `raicode` to sign in, then `raicode manage fix-certs` and
  open a new terminal.
